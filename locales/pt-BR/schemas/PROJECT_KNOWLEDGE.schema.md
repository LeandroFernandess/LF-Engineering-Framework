# Schema de PROJECT_KNOWLEDGE

## Objetivo

Estrutura canônica para a documentação de extração de conhecimento do projeto
produzida pelo Engineering Knowledge Extractor Agent.

## Seções obrigatórias

- Resumo do projeto
  - Nome do projeto
  - Objetivo de negócio
  - Problema resolvido
  - Escopo

- Stack técnico
  - Linguagens e runtimes
  - Frameworks
  - Bibliotecas
  - APIs
  - Bancos de dados
  - Serviços de nuvem
  - Integrações externas
  - Ferramentas de desenvolvimento

- Decisões de engenharia
  - Padrões arquiteturais
  - Organização de pastas
  - Padrões de design
  - Trade-offs principais
  - Racional das decisões

- Novas tecnologias
  - Nome e versão da tecnologia
  - Finalidade no projeto
  - Já documentada no Framework? (Sim/Não)
  - Recomendação de documentação

- Novo conhecimento de engenharia
  - Domínio do conhecimento
  - Descrição
  - Por que é novo
  - Relevância para o Framework

- Melhorias sugeridas para o Framework
  - Módulo ou agente alvo
  - Mudança recomendada
  - Racional
  - Prioridade (Crítica / Alta / Média / Baixa)

- Resumo das recomendações
  - Lista priorizada de todas as recomendações

## Validação

- Todos os achados devem referenciar evidências específicas do projeto.
- As tecnologias listadas devem estar presentes nos artefatos do projeto.
- O conhecimento novo deve ser claramente distinguido do conhecimento existente
  do Framework.
- Toda recomendação deve referenciar um módulo, módulo de Knowledge ou Agent
  específico do Framework.
- Toda recomendação deve incluir um nível de prioridade.
- Este documento não deve modificar o Framework.
- Avaliações subjetivas sem evidência não devem ser incluídas.

## Restrições

- Este documento recomenda; não prescreve.
- Todas as recomendações exigem revisão humana antes de mudanças no Framework.
- Este documento é somente leitura em relação ao LF Engineering Framework.
