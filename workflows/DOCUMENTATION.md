# Documentation Workflow

## Purpose

Workflow for creating or updating engineering documentation as a first-class project artifact.

## Steps

1. Identify the audience and decision the document supports.
2. Consult current project artifacts and `knowledge/INDEX.md`.
3. Update the relevant document in `docs/` or `.ai/`.
4. Keep documentation factual, current and traceable to decisions.
5. Review for contradictions against PRD, architecture, ADRs and sprint tasks.
6. For web or visual projects, synchronize `docs/PERFORMANCE_VALIDATION_REPORT.md`
   with the approved route/profile targets, budgets, implementation and QA
   evidence. Keep missing field data and exceptions explicit.

## Expected Outputs

- Updated `docs/PRD.md`, when product scope changes.
- Updated `docs/ARCHITECTURE.md`, when technical design changes.
- Updated `docs/SPRINTS.md`, when delivery planning changes.
- Updated `docs/ADR.md`, when a significant decision is made.
- Updated `docs/PERFORMANCE_VALIDATION_REPORT.md`, when a web or visual project
  has performance evidence or an accepted exception.
- Updated `.ai/artifacts.md`, when generated outputs or references change.
